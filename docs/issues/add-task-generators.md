# Add the linear-teacher, object-action and what-where task generators

The study trains small feed-forward networks on three tasks and asks whether their hidden neurons become modular for the task variables ("factors"). This item adds the three datasets to the library, each carrying its ground-truth factors so a later item can measure mutual information between neurons and factors. They plug into the existing `Dataset` / `DataConfig` / `get_dataset` machinery (same cache layout, same CLI `init --set data.task=...`), and the existing position task must be unchanged.

## Interfaces
- `config.DataConfig` gains (all with defaults; strict pydantic as elsewhere; constrained types):
  `task: Literal["position","linear_teacher","object_action","what_where"] = "position"`;
  linear teacher: `n_latents: PosInt = 3` (k), `latent_range: PosFloat = 1.0` (a);
  object-action: `grid_size: PosInt = 5` (G), `max_objects: NonNegInt = 3` (A);
  what-where: `n_motifs: PosInt = 8` (m).
  The existing fields keep their meaning for the position task. For linear_teacher `D_in` is the spec's m (both X and Y have m features, m > k, validated). For object_action and what_where the input dimension is fixed by the task (2*G*G and 81), so `D_in` must equal it: `make_dataset` raises a ValueError naming the value to set otherwise; the output dimension is likewise fixed (5; 9 + n_motifs).
- `data.task_dims(cfg: DataConfig) -> tuple[int, int]`: (D_in, D_out) of the task for a config (the position task: (cfg.D_in, cfg.d)); pure, used later by the sweep runner to set D_in.
- `data.Dataset` gains optional trailing fields `factors: dict[str, Tensor] | None = None`, `groups: dict[str, list[str]] | None = None`, `extras: dict[str, Tensor] | None = None` (frozen dataclass; positional construction by existing code keeps working). `factors` maps a factor name to a (P,) tensor: int64 dtype means categorical (labels 0..C-1), float dtype means continuous. `groups` maps a group name to the factor names it contains (the unit over which modularity is later scored; a factor that is its own group appears as a singleton group). `extras` holds tensors needed to draw examples. `get_dataset` persists and reloads all three (they must satisfy the weights_only artefact rules in cache.py; groups is dict[str, list[str]]).
- New module `fct/tasks.py` with the pure generators (CPU generator seeded with cfg.seed, then moved to device, exactly as make_dataset does: output must not depend on device) that `make_dataset` dispatches to:
  - linear teacher: Z (P, k) iid uniform on [-a, a]; W_X, W_Y in R^{m x k} with iid N(0, 1/k) entries (fixed by the seed); x = Z W_X^T, y = Z W_Y^T (both (P, m)). factors: `z0`..`z{k-1}` float (the columns of Z); groups: one singleton group per latent; D_in = D_out = m. extras: `W_X`, `W_Y`.
  - object-action: G x G grid, cells indexed row-major (cell = row*G + col). Per sample: the agent's cell uniform over the G*G cells; the number of objects uniform over {0, ..., A}; object cells distinct, drawn uniformly without replacement from ALL G*G cells (an object may sit under the agent: that is the "coincides" case). x = concat(one-hot agent cell (G*G), binary object map (G*G)), shape (P, 2*G*G); y = optimal action, shape (P, 5), columns [stay, up, down, left, right], up = row-1, down = row+1, left = col-1, right = col+1. Optimal action: with Manhattan distance, find the nearest object(s); stay = 1 iff there are no objects or the agent is on an object (distance 0); otherwise stay = 0 and each of the four moves is 1 iff it lowers the minimum Manhattan distance to the object set by exactly 1 (so a diagonal nearest object gives two 1s, and several equally near objects give the union). Implement the pure vectorised `tasks.optimal_actions(agent_rc (P,2) int, objects (P,G,G) bool) -> (P,5) float`. factors: `position` (int64 in [0,G*G)), `object_{i}` for every cell i (int64 0/1), `action_{stay,up,down,left,right}` (int64 0/1); groups: {"position": ["position"], "objects": [all object_i], "actions": [all action_*]}. Raise if A > G*G.
  - what-where: a 9x9 micro-grid divided into a 3x3 macro-grid of 3x3 cells. The motif library is all 2^9 - 1 = 511 non-empty binary 3x3 patterns (note: the PI's text says "510 valid configurations" while also counting the all-on pattern, which gives 511; use 511 and state this in the docstring); the m = n_motifs motifs are chosen uniformly without replacement (seeded; assert m <= 511). Each sample draws a macro-cell `where` uniform over 9 and a motif `what` uniform over m, independently; x (P, 81) is the micro-grid (row-major, pixel (3R + r, 3C + c) = motif[r*3 + c] inside macro-cell (R, C), zero elsewhere); y (P, 9 + m) = concat(one-hot where, one-hot what). factors: `where` (int64, 9 categories), `what` (int64, m categories), each its own singleton group. extras: `motifs` (m, 9) the chosen patterns.
  - position task: add factors `y0`, `y1`, ... (the columns of y, float) and singleton groups; nothing else about it changes (x and y values bit-identical to before).
- Add `tmp/` to `.gitignore` (the PI's local scratch directory).

## Acceptance criteria (tests; synthetic, CPU, tiny sizes)
- Position task: x and y of `make_dataset` are bit-identical to the values on main for a fixed config (compare against values produced from `git show main:fct/data.py` or a stored tiny reference computed before you change anything); the new factors equal the columns of y.
- Every task: shapes, dtypes (x, y floating; factor dtypes as specified), same config -> identical data, a different seed -> different data, `task_dims` matches the dataset, `get_dataset` round-trips factors/groups/extras through the cache (a second call loads from disk and equals the first), and the mismatch error for a wrong D_in.
- Linear teacher: z within [-a, a] and roughly uniform (mean ~ 0, variance ~ a^2/3 at P = 20000); least squares from x recovers z exactly (residual ~ 0) and the map x -> y has rank k; m <= k is rejected.
- Object-action: `optimal_actions` equals a brute-force oracle (written independently in the test: for each candidate move compute the new minimum Manhattan distance) on EVERY (agent cell, object subset) of a 3x3 grid (9 x 512 cases), including: no objects -> only stay; on an object -> only stay; a diagonal nearest object -> exactly two moves; two equally near objects in opposite directions -> both moves. The dataset's x decodes back to the factors (`position`, `object_i`), y equals the action factors, object counts are uniform on 0..A (loose chi-square or tolerance on frequencies at P = 20000), objects are distinct per sample, and A > G*G raises.
- What-where: x is reconstructed exactly from (`where`, `what`, `extras["motifs"]`); y is the two concatenated one-hots; the motifs are distinct and non-empty; `where` and `what` are uniform and independent (loose tolerance); m > 511 raises.
- All existing tests pass (update only what the changed config hashes force); ruff clean; docs/design.md updated for DataConfig, Dataset, tasks.py, task_dims.
