# Add notebooks/playground.ipynb: define, train and explore an experiment in one notebook

PI request (2026-11-02). Add a scratch notebook that uses the exp pipeline end to end:
1. define an experiment in the notebook;
2. train its settings in real time, in the kernel, with progress visible as it runs;
3. leave room for playing with analysis functions.

It has no builder script (unlike the other notebooks/*.ipynb, which are generated by notebooks/build_*.py), so it is written and edited as a notebook directly. The PM has already moved the old root-level playground.ipynb, which was untracked, to notebooks/archive/; do not touch it.

## Inputs / outputs / interfaces
Use the public exp API only; do not reimplement anything the library has. The relevant functions:
- `fct.exp`: `preset`, `with_axes`, `ExpConfig.model_validate`, `save_exp`, `load_exp`, `same_experiment`, `get_setting`, `setting_config`, `setting_status`, `setting_dir`, `run_setting(exp, index, root, log=print)`, `find_setting_dir`.
- For loading a trained setting, read `fct/phase_view.py` (`load_phase_run`), `fct/exp_view.py` (`load_setting_data`) and `fct/spatial_view.py`, and use whichever library loader fits.
- Read README.md's experiment section and fct/exp.py's ExpConfig docstring first.

Notebook structure, as markdown and code cells:
1. **A short header** (markdown) saying what the notebook is for.
2. **Parameters cell**:
   - `ROOT`: default `None`, which means `$FCT_PLAYGROUND_ROOT` if set, else `<repo>/tmp/playground`, the git-ignored scratch dir. Find the repo root from the notebook's location or `fct.__file__`, not a hard-coded absolute path.
   - `PRESET`: the base preset name.
   - `OVERRIDES`: a dict of base-field overrides, e.g. `{"n_epochs": 2000, "N": 64}`.
   - `AXES`: a dict of axis name to list of values, or None to keep the preset's.
   - `DEVICE`.
   - The defaults must train in about a minute on CPU in total; pick a small preset such as `spatial_tiny` or `tiny` and shrink it with OVERRIDES/AXES.
3. **Define the experiment**:
   - Build the ExpConfig from the preset plus OVERRIDES via validation (`ExpConfig.model_validate({**base.model_dump(), **OVERRIDES})`, then `with_axes` if AXES is given).
   - Print its settings (index, axis values, status).
   - Save it to ROOT. If ROOT already holds a *different* experiment (`not same_experiment`), raise a clear error telling the user to change ROOT or delete it. Never silently overwrite it.
4. **Train**:
   - Loop over the settings and call `run_setting(..., log=print)` so log lines stream in the cell as training runs.
   - run_setting already resumes partial runs and skips done ones, so re-running the cell is cheap; say so in a comment.
   - After training, plot each setting's loss curve from its saved history with plain matplotlib.
5. **Load**: a cell that loads one chosen setting (`SETTING` = a dict of axis values or an index) into named variables: the config, the trained net, the training data, and the history. The analysis cells use these.
6. **Analysis playground**:
   - A markdown cell listing the main analysis entry points, with one line each, e.g. `fct.analyse` (r_squared, pick_examples…), `fct.tuning`, `fct.spatial` (build_spaces, data_kernel…), `fct.phase_view` (layer_priors, member_view…), `fct.exp_view` (tuning_view…). Check each name exists.
   - One or two short example cells, e.g. the R² of the trained net on its training data and one simple plot.
   - A few empty code cells.

Keep cells short. The library computes and the notebook only draws (house style; see notebooks/phase_transition_exp.ipynb). Strip outputs before committing.

Tests: add tests/test_playground_notebook.py, which executes the notebook top to bottom (nbclient or nbconvert, whichever the repo already uses: see how tests/test_build_exemplar.py and notebooks/build_spatial.py's execute_notebook do it). It sets FCT_PLAYGROUND_ROOT to a tmp_path and uses the notebook's own small defaults, shrunk further through parameter injection if the repo has a helper for that. It asserts:
- it executes without error;
- exp.json is written;
- every setting's train status is done;
- a second execution in the same ROOT trains nothing new (each setting reports done and is skipped);
- a different experiment already in ROOT makes the define cell raise.
Keep the test's runtime small, well under a minute if possible.

## Acceptance criteria
- notebooks/playground.ipynb exists, has no outputs committed, and runs top to bottom on CPU with its defaults.
- It uses only the public exp API to define, save and train, and library loaders to load.
- A different experiment in ROOT is refused, not overwritten; re-running the train cell skips finished settings.
- The test above passes, the full suite passes, and `ruff check` and `ruff format --check` on fct and tests are clean.
